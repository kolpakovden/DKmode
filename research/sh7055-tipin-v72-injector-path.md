# v72 — SH7055 OEM Tip-in: от сигнала TPS до аппаратного импульса форсунки

**Дата:** 2026-10-26. **Статус:** статический read-only анализ. Прошиваемых BIN и патчей нет. Работа не связана с Delta MAP.

## 0. Исходные данные и статусы

- Анализ выполнен на proxy-ROM `forester_sg9_sti_MAP_IAT_GM_dMap_v63.bin` (SHA-256 `2ee7056b…ebc6eef8`). Код Tip-in и OS совпадает со всеми proxy v63–v70 (`sh7055_task_v70_audit.py` проверяет каждый по собственному SHA-256). Все находки ниже — **`PROXY-CONFIRMED`**, если не указано иное. Чистый v39 (`43a4751d…`) **не проверялся**: файла нет.
- Значения калибровок взяты из v63 и **не равны v39** (например, `0x58DA8`: v63 = 385, v39 = 25, v25 = 250).
- Внешние источники (`REFERENCE`): fenugrec/npkern (адреса регистров SH7055) и RomRaider-логгер из `forester_A2WC012E` для ECU ID `1356212FFF`.
- Время и частоты: Pφ = 20 МГц — **вывод**, не измерение (см. v71 и §3.4 ниже). 8 мс для задачи №9 — расчётная оценка.

## 1. Исправление аудита v70

`tools/analysis/sh7055_task_v70_audit.py` переписан под раскладку `0x469C + 16·id`:

- для всех 19 задач выводятся поля `flags/priority/state_ram/entry/activation_limit`;
- проверяются инструкции, которые доказывают раскладку: `0x37C8` (индекс ×16), `0x37F4` (`@(8)` — точка входа), `0x38EA` (`@(2)` — приоритет), `0x3F50` (`@(12)` → лимит активаций);
- известные ROM закреплены по SHA-256: v39/v25 → `ROM-CONFIRMED`, семь уникальных proxy-сборок → `PROXY-CONFIRMED`. Неизвестный хеш отклоняется;
- задача №9: запись `0x472C`, приоритет 2, состояние `0xFFFF71E4`, вход `0x6330`, лимит 2 — совпадает на всех proxy.

## 2. Карта исполнения Tip-in (сигнал → аппаратный выход)

```text
AD1 ADDR13 (0xFFFFF822)  --ISR ADI1 0x6B38..-->  RAM16 0xFFFF9036
  │  задача №9: 0x7618  (проверка диапазона, удержание; ×5/65536 V ×25)
  ▼
0xFFFF90E4  = 25·V   ── 0x17150: фильтр → 0xFFFF B01C
  │  0x1716E: B020 = max(90E4 − 80E8 − 80A0, 0)
  │  0x1718E: B024 = B020 | 6.0 при флагах C4D1.7/.6
  ▼
B024 «Throttle Plate Opening Angle» (RomRaider E38: % = x/0.84)
  │  0x171C6: B028 = B024[n] − B024[n−2]      («Tip-in Throttle», E54)
  ▼
0x24A04  OEM Tip-in (в той же задаче №9)
  │  gates + B80C = T(Δ)·K_boost·K_ECT  [мкс]   («Tip-in Enrichment», E55)
  │  B80C ≥ ROM_f[0x58DA8] → B810 = B80C, B824 = B80C + B8D8 (латентность, E50)
  ▼
0xD754(0, 4, &B810) → ROM 0xF6AC → 0xF75C[4] = {0xFFFF, 1, 0x114BC} → прямой вызов
0x114BC → 0x272F8(B810): для i = 0..3 → 0x27344(i)
  │  ticks = FTRC(B810 / 0.25)            ; единицы 0.25 мкс
  │  пропуск, если бит i в RAM16 0xFFFFB434 установлен
  │  пропуск, если ROM8[0x41130+i] ≠ 1
  ▼
0x91F4 → BRA 0x985C(ch = ROM8[0x4112C+i], ticks)
  │  DCNT = ticks/16 (+ RAM 0xFFFF91E0/16 для нового импульса)
  ▼
0x9B10 → 0xD964: запись u16 в DCNT8x (0xFFFFF640 + 2·ch)        ← АППАРАТНАЯ ЗАПИСЬ
0x985C: DSTR8 (0xFFFFF666) = 1<<ch  — старт one-shot down-counter ← АППАРАТНЫЙ ЗАПУСК
        TSR8 (0xFFFFF66A) = ~(1<<ch), TIER8 (0xFFFFF66C) |= 1<<ch
конец импульса: вектор 152..155 (OSI8A..D) → 0x58CC.. (сброс TSR8) → 0x9074 → 0x978C
```

## 3. Исполнительный путь через `0x985C` — доказательства

### 3.1. Таблица каналов `ROM 0xF4EC` (записи по 12 байт)

| ch | +0 счётчик длительности | +4 регистр сравнения | +8 маска |
|---|---|---|---|
| 0 | `0xFFFFF640` DCNT8A | `0xFFFFF444` GR1A | `0x0001` |
| 1 | `0xFFFFF642` DCNT8B | `0xFFFFF446` GR1B | `0x0002` |
| 2 | `0xFFFFF644` DCNT8C | `0xFFFFF448` GR1C | `0x0004` |
| 3 | `0xFFFFF646` DCNT8D | `0xFFFFF44A` GR1D | `0x0008` |

Имена регистров взяты по npkern `reg_defines/7055_350nm.h` (`st_atu8` @ `0xFFFFF640`: DCNTA…P, RLDR `F660`, TCNR `F662`, OTR `F664`, DSTR `F666`, TCR `F668`, TSR `F66A`, TIER `F66C`; `st_atu1` @ `0xFFFFF440`: TCNTA `F440`, GRA…GRD `F444…F44A`).

`0x4112C` = `0,1,2,3` (цилиндр i → канал i), `0x410D8` = `1,2,4,8`, `0x41130` = `1,1,1,1` (значения v63).

### 3.2. Функции

- **`0x9B10(ch, n)`** — установить длительность: если `n > 0xFFFF`, в DCNT пишется `0xFFFF`, остаток `n − 0xFFFF` сохраняется в RAM32 `0xFFFF91F4 + 28·ch` (`0x9B1E..0x9B52`). Затем `JSR 0xD964(ROM32[0xF4EC + 12·ch], n)`.
- **`0xD964(reg, value)`** — с поднятым IMASK (`0x2088`, R5 = `0xE0`) дважды делает `MOV.W R0,@R2` по адресу регистра (`0xD97A`, `0xD980`), затем восстанавливает SR (`0x2098`). Это **последняя доказанная запись в периферию**.
- **`0x9B60(ch)`** — оставшаяся длительность = текущий DCNT + сохранённый остаток.
- **`0x985C(ch, amount)`** — R5 = `amount` в единицах 0.25 мкс, сдвиг `SHAR×4` → /16. Состояние канала — RAM `0xFFFF91E4 + 28·ch` (байт +24 «импульс идёт / запланирован», +22, слово +20, long +12).

  | Ветвь | Условие | Действие |
  |---|---|---|
  | A `0x98A4` | state.b24 == 1 (импульс идёт) | `total = amount/16 + 0x9B60(ch)` с ограничением 0x7FFF; оценка окна по TCNT1A `0xFFFFF440` и state.w20; при необходимости TIER8 &= ~mask, b24 = b22 = 0; затем `0x9B10` и `DSTR8 = mask`, `TSR8 = ~mask` — **продление текущего импульса** |
  | B1 `0x9936` | DCNT == 0 (канал свободен) | `0x9B10(ch, (amount + RAM32[0xFFFF91E0])/16)`, `DSTR8 = mask`, b22 = 1 — **новый отдельный асинхронный импульс** |
  | B2 `0x9968` | DCNT ≠ 0 и бит в DSTR8 установлен | `0x9B10(ch, amount/16 + 0x9B60(ch))`, `DSTR8 = mask` — продление идущего счёта |
  | B3 `0x99B8` | DCNT ≠ 0, счёт не запущен | пересчёт с `0xFFFF91E0` и окном TCNT1A: либо объединение с ожидающим импульсом (state.l12), либо `TSR8` clear, `0x9B10`, `DSTR8 = mask`, `TIER8 |= mask`, b24 = b22 = 1 |

  Вход и выход — под `0x2088`/`0x2098` (IMASK 14).

### 3.3. Ответы на вопросы этапа

1. **Отдельный импульс или изменение существующего?** И то и другое, в зависимости от состояния канала (ветви A/B2 — продление, B1 — новый импульс, B3 — слияние с запланированным). `PROXY-CONFIRMED`.
2. **Добавка «мёртвого времени».** RAM32 `0xFFFF91E0` прибавляется только при новом импульсе (B1, B3), но не при продлении. Та же переменная входит в основной расчёт импульса (`0x9142`, `0x94B2`, `0x96B8`, `0x972C`). По смыслу это компенсация латентности форсунки в единицах 0.25 мкс — `inferred`. Писатель `0xFFFF91E0` не найден.
3. **Общий ресурс с основным впрыском.** `0x9B10` вызывается ещё из `0x92D8, 0x93D2, 0x942A, 0x96F4, 0x9764, 0x9808, 0x9ABA`, то есть основной импульс использует те же DCNT8A–D. `PROXY-CONFIRMED`.
4. **Выбор цилиндра.** Tip-in применяется ко **всем 4 каналам сразу** (цикл `0x27306..0x27310`), кроме запрещённых битом в RAM16 `0xFFFFB434` или ROM8 `0x41130+i ≠ 1`. Маска `B434` собирается в `0x1DExx` из битов статусов (`0xB832`, `0xB898`, `0xB89C` и др.); её смысл (диагностика/отсечка) — `unknown`.
5. **Связь с фазой.** Для одновременного Tip-in прямой привязки к углу коленвала нет: импульс запускается немедленно через DSTR8. Угловая арифметика (`0x273BC`, модуль `0x2D00000` = 720° в 16.16) и сравнение по TCNT1A есть только в логике слияния с запланированными основными импульсами. Полная фазовая модель основного впрыска не разобрана.
6. **Конец импульса.** Векторы 152–155 (`OSI8A–D`, ROM `0x7FEB0..0x7FEBC`) — реальные ISR: `0x58CC`: `TSR8 = 0xFFFE`, `JMP 0x9074(R4 = 0)`, далее `BRA 0x978C`. `0x978C` (подгрузка остатка `> 0xFFFF`, сброс состояния) **не разобран**.

### 3.4. Единицы и тактирование

| Звено | Доказательство | Статус |
|---|---|---|
| `T(Δ)` в мкс | дескриптор `0x54910` = `{n=18, тип u16, ось 0x59B3C, данные 0x59B84, mult 4.0, off 0}`; интерполятор `0x209C` применяет `raw·mult+off` (`0x20BC..0x20C2`). Сырые данные — единицы 4 мкс (RomRaider: `x·0.004` мс), значит результат — мкс | PROXY-CONFIRMED (код) + REFERENCE (единицы raw) |
| `B80C`, `B810` в мкс | `B824 = B80C + B8D8`, где `B8D8` = «Injector #1 Latency», RomRaider `x·0.001` → мс | PROXY-CONFIRMED + REFERENCE |

| Итог | 4 мкс/отсчёт ⇔ Pφ = 20 МГц | **третье независимое подтверждение Pφ = 20 МГц** (после SCI2 = 4800 бод и CMT1 = 1 мс) — `inferred`, сильное |

### 3.5. Исправление исторической интерпретации порога (важно)

В `0x24B0C..0x24B1E` порог `ROM_f[0x58DA8]` сравнивается с `B80C`, а `B80C` уже в мкс (mult 4.0 применён в `0x209C`). Значит порог тоже в **мкс**:

| ROM | raw `0x58DA8` | По коду | В старых документах (`×0.004`) |
|---|---|---|---|
| v25 | 250.0 | **0.250 мс** | 1.000 мс |
| v39 | 25.0 | **0.025 мс** | 0.100 мс |

Вывод `forester_A2WC012E/docs/known-results.md` («порог 1.000 мс, пересечение ≈ 6.2 % ΔTPS») основан на масштабе `×0.004` и, по коду, **завышает порог в 4 раза**. Статус — `PROXY-CONFIRMED`: код `0x24A04` идентичен v25/v39 (v69). Переоценку на точных v25/v39 и логах нужно сделать в v73. Та же проверка единиц нужна для CarBerry `0x293FA` (96 → «0.384 мс»).

## 4. Коррекции TPS: `0xFFFF80E8` и `0xFFFF80A0`

Обе переменные хранятся в области `0xFFFF80xx` и пишутся только через `0x38174` (запись обучаемого значения), а проверяются через `0x3827E`. По смыслу это сохраняемые обучаемые значения (backup) — `inferred`.

### `0xFFFF80E8` — обученная точка «полностью закрыто» (нулевая точка) заслонки

- Значение по умолчанию: `0x168AC..0x168C2` пишет `ROM_f[0x57678]` = 10.314 в `80E8` и в парный `80F0`.
- Обновление: `0x16B22..0x16B4C` — `80E8 = clamp(…, 9.193, 20.807)` (`ROM 0x576D0/0x576D4`, clamp-хелпер `0x2464`), аналогично `80F0`.
- Единицы те же, что у `90E4` (25·V): окно 9.19…20.81 ≈ 0.37…0.83 В.
- Смысл «learned closed throttle» — `inferred` (структура доказана, термин — интерпретация).

### `0xFFFF80A0` — ограниченная поправка-рассогласование

- Группа из четырёх значений `8078 / 8080 / 8098 / 80A0`. Умолчания (`0x15304..0x1532E`): 21.0, 21.0, 21.0, **0.0**.
- Обновление в `0x15890..0x1597A` при условиях: бит 7 `AFBC` = 0, слово `AFB8 ≥ ROM16[0x575BC]`, проверка статуса `0x40B0(80A8)`, бит 6 `AFBC` = 0, `AFBA ≥ ROM8[0x575A8]`:
  - `8078 = clamp(RAM_f[0xFFFFAFA8], 15.209, 26.791)`;
  - `8098 = clamp(B01C, 15.209, 26.791)`, где `B01C` — отфильтрованный `90E4` (`0x17150`, коэффициент `ROM_f[0x575FC]` = 0.25);
  - `8080 = clamp(f(AFAC), 11.893, 30.107)`;
  - **`80A0 = clamp(8078 − 8098, −0.428, +0.428)`** (`ROM 0x57654/0x57658`).
- То есть `80A0` — малая (±0.428 ед. ≈ ±17 мВ по шкале ×25) обучаемая разность между обученным положением другого сигнала (`AFA8`) и обученным фильтрованным TPS. `AFA8` не трассирован — `unknown`. Возможно, это опорное положение от модели или второго датчика.

### Итог по входу

`B020 = max(TPS·25V − learned_closed(80E8) − bounded_offset(80A0), 0)` → открытие заслонки от обученного нуля. Масштаб: 84 ед. = 100 % (RomRaider E38 `x/0.84`) — `REFERENCE`.

### Происхождение AN13/AN14

- Код: `0x9036` ← AD1 ADDR13 (`0xFFFFF822`), `0x9038` ← ADDR14 (`0xFFFFF824`), ISR `0x6B38..0x6BC2`. `PROXY-CONFIRMED`.
- Для того же ECU ID `1356212FFF` RomRaider-логгер называет `0xFFFFB024` **«Throttle Plate Opening Angle»**, а педаль описывает отдельным SSM-параметром (P30 «Accelerator Pedal Angle»). Значит, канал AN13 → `90E4` → `B024` — **датчик положения дроссельной заслонки (main)**, AN14 → `90E8` — по всей видимости, sub-датчик (обратный отрезок 1…5 В). Статус `REFERENCE + PROXY-CONFIRMED` (код + сообщество); распиновка разъёма ECU не проверялась.

### Что из CarBerry уже есть в Subaru

- двухшаговая Delta TPS;
- порог по Δ и порог по величине;
- таблица `T(Δ)` с компенсациями;
- асинхронный дополнительный импульс по всем цилиндрам;
- адаптация нулевой точки TPS.

Функционально «узел CarBerry» в штатной прошивке **уже присутствует**.

### Где реальные различия (подтверждённые или вероятные)

1. **Временное окно Δ**: ≈ 16 мс у Subaru против ≈ 30 мс у CarBerry. Оба значения условные, но различие примерно в 2 раза при одинаковом приращении положения означает разную чувствительность к скорости нажатия.
2. **Разрешение Δ**: float у Subaru против 8-битного q8 у CarBerry с другой базой. Пороги `0.2` и `0x82` напрямую не сопоставимы.
3. **Ограничители серии** (`B818` / `B814` / таймауты) у Subaru; аналог у CarBerry не установлен.
4. **Порог на величину**: исторический вывод «Subaru 1.000 мс vs CarBerry 0.384 мс» по коду Subaru неверен (v25 = 0.25 мс). Сравнение нужно переделать после проверки единиц CarBerry.

### Потенциально имеет смысл для DKmode — только после v73

Не предлагать новый алгоритм, пока не доказана разница. Кандидаты на исследование:

- калибровочный (не кодовый) анализ: окно, порог `0x58DA4`, лимиты серии;
- логирование `B028/B80C/B818/0xFFFF94E4` на автомобиле для проверки реальной частоты срабатывания.

## 6. Точки обрыва и неизвестные для v73

1. Разбор `0x978C` (конец импульса, подгрузка остатка, сброс state) и ветви B3 (`0x99B8..0x9A3E`) с окном по TCNT1A.
2. Такт ATU1 TCNT1A (`TCR1A` `0xFFFFF45D`) — нужен для единиц окна в B3.
3. Привязка выходов TO8A–D (через `TCNR` `0xFFFFF662` = `0xCFCF`, `OTR` `0xFFFFF664` = `0x4F00` по `0x4BFC..0x4C06`) к драйверам форсунок — нужна схема или плата. Сейчас вывод «DCNT8A–D = форсунки» основан на структуре (4 канала, маски цилиндров, 720°, общий код с основным импульсом) — `inferred`, сильное.
4. Писатель `0xFFFF91E0` (латентность в единицах 0.25 мкс?).
5. Смысл маски `0xFFFFB434` и ROM8 `0x41130`.
6. Источник `RAM_f[0xFFFFAFA8]` (вход `80A0`) и `AF08/AF94` (вход компенсации `0x5455C`; по REF — «boost error»).
7. CarBerry: проверить по коду HC16 единицы `0x293FA` и способ подачи импульса (QADC → … → выход TPU/GPT).
