### 2.1. Выводы

1. **CMT1 и Pφ = 20 МГц подтверждены на автомобиле.** Два независимых лога дают одинаково 500.12 отсчётов/с, то есть тик 1.000 мс и период активации задачи №9 **8.00 мс**. Отклонение +0.025 % одинаково в обоих логах. Это систематика часов ПК и (или) кварца ECU (типичные допуски — десятки ppm), а не свойство прошивки. Вариант Pφ = 40 МГц (1000 отсч./с) исключён. Статус «8 мс — расчётная оценка» из v71–v75 повышается до **«измерено (период активации)»**. Период *исполнения* и джиттер задачи по-прежнему не измерены.
2. **Адрес `0xFFFF94F0` правилен для ROM в автомобиле.** Случайная ячейка RAM не увеличивалась бы ровно на 500/с. Это косвенное подтверждение совместимости ROM в ECU с кодом v63–v70 по ядру ОС, но **не** замена проверки SHA-256: ROM всё ещё нужно идентифицировать (шаг S0).
3. **Потерь активаций на ХХ нет:** `94E4` = 0 за 5.7 мин.
4. **Tip-in на ХХ не срабатывал,** и это согласуется с моделью: `B818` = 0, `B821` = 255 (с момента включения не было ни одного события), `|B028|` ≤ 0.122.
5. **Разрешение TPS по ROM-шкале подтверждено:** шаг `B024` = 0.122 = 25 · 5 В / 1024, то есть эффективно 10-битный АЦП в шкале `90E4 = 25·V` (v72 §4). Отсюда:
   - шум ХХ — ±1 младший разряд (0.122 ед. ≈ 0.145 %);
   - порог Δ v39 (0.2) лежит между 1 и 2 разрядами: событие начинается с изменения ≥ 2 разрядов за два прогона (≈ 16 мс);
   - порог v63 (0.5) соответствует ≥ 5 разрядам.
6. **Шаг опроса растёт на ≈ 2 мс на каждый добавленный адрес:** S1 → S2 добавили 11 адресов, шаг вырос на 22 мс. Это совпадает с моделью непрерывного ответа ECU (≈ 2.083 мс на байт при 4800 бод, v75 §3). Минимальный набор для перегазовок даст шаг ≈ 50–60 мс, то есть ≈ 7 прогонов задачи на отсчёт.
