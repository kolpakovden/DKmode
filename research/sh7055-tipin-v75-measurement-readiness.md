# v75 — готовность к измерениям OEM Tip-in на EJ255

**Дата:** 2026-10-26. **Статус:** инструменты готовы и проверены на синтетических данных. **Верификация на автомобиле не проводилась** — реальных логов с новыми параметрами пока нет. ROM не изменялся, BIN не создавался, впрыск не затрагивается. Работа не связана с Delta MAP.

## 1. Аудит модели v74

| Пункт | Как в коде `0x24A04` | v74 | Исправлено в v75 |
|---|---|---|---|
| Порядок условий | `B821++` → сбросы (Δ < 0 или по `B821`) → Δ ≥ min → `B818` < max → `B018.1` → `B469.7` → `B814` < max → `B80C` → порог величины | совпадал | — |
| Граница Δ | выход при `min > Δ` (`0x24AA0 FCMP/GT`) — **равенство проходит** | совпадал | тест |
| Граница `B814` | продолжение только при `max > B814` — **равенство блокирует** | совпадал | тест |
| Граница величины | выход при `min > B80C` — **равенство срабатывает** | совпадал | тест |
| Сбросы `B818/B814` | `CMP/HS`, `B821 ≥ ROM8[0x58853/54]`; `MOV.B` с расширением знака сохраняет беззнаковый порядок | совпадал | тест, граница 21/22 |
| Δ < 0 | `B818 = 0`, `B814 = 0`, затем проверка Δ (заведомо отказ) | совпадал | тест |
| Интерполяция `0x2684/0x209C` | клип ниже `axis[0]` и при `x ≥ axis[n−1]`; при `frac == 0` значение берётся напрямую; `raw·mult + off` при типе ≠ 0; типы `0x00` float, `0x04` u8, `0x08` u16, `0x0C` s8, `0x10` s16 (диспетчер `0x20CC`) | эквивалентно | поиск индекса переписан как в коде |
| float32 | вся арифметика SH-2E — binary32 | Python double | округление до binary32 на каждой операции (`--no-f32` для сравнения). На proxy-сценариях результат совпал; FMAC считается с двумя округлениями — на точных границах возможна разница в 1 ulp |
| История TPS | ROM: сдвиг `B034 ← B030 ← B02C ← B024` | первые 2 прогона пропускались | история заполняется первым отсчётом (Δ = 0) |
| Джиттер / потери | активация каждые 8 тиков, лимит 2 | только джиттер | `--drop-prob` (потерянные активации, ср. `0xFFFF94E4`) |
| Входной CSV | — | поиск O(n) | бинарный поиск; **проверка частоты входа** |

### 1.1. Режимы входа модели

| Режим | Когда | Метка в отчёте |
|---|---|---|
| synthetic | `--ramp`, `Profile` | `MODEL-SYNTHETIC` |
| daq | медиана шага ≤ T/4 и p95 ≤ T/2 (при T = 8 мс: ≤ 2 и ≤ 4 мс) | `MODEL-ON-DAQ-INPUT` |
| ssm | иначе | работа запрещена; с `--force-coarse` — `MODEL-ON-COARSE-INPUT` |

Модель **не** восстанавливает события из SSM-лога. Для SSM используется анализатор §4, который работает только со счётчиками.

### 2.1. Параметры addon (ECU ID `1356212FFF`)

|---|---|---|---|---|---|

| E7504 | `0xFFB814` | float / 4 | BE | raw | `0x24A38`, `0x24AD0` |
| E7505 | `0xFFB8D8` | float / 4 | BE | мс = x·0.001 | `0x24A14`; `0x26C38` (= `91E0`·0.25) |
| E7506 | `0xFFB818` | uint8 / 1 | — | шт. | `0x24A34`, `0x24AA6` |
| E7507 | `0xFFB821` | uint8 / 1 | — | прогоны | `0x24A2A` |
| E7508 | `0xFF94E4` | uint8 / 1 | — | шт., насыщение 255 | `0xD03C` (`0x94DB` + 9) |
| E7509 | `0xFF94F0` | uint16 / 2 | BE | шт., переполнение 65536 | `0xD2B8` |
| E7510 | `0xFFB810` | float / 4 | BE | мс = x·0.001 (только при срабатывании) | `0x24B2E` |

- Синтаксис взят из действующего логгера `forester_A2WC012E` (`<ecu id><address length>`, `storagetype="float"/"uint16"`, 24-битная запись RAM `0xFFxxxx`). E38/E54/E55/E50 уже есть в исходном логгере по тем же адресам. E7501–E7505 дублируют их под отдельными именами, чтобы исследовательский набор был самодостаточным.
- `merge_logger_addon.py --check` проверяет: корень `<ecuparams>`, формат id и адреса, длину по `storagetype`, наличие ECU ID, единицы и выражение. При слиянии дополнительно: нет совпадений id и имён с оригиналом, результат парсится, каждый id встречается ровно один раз, файл-оригинал не перезаписывается (тест проверяет SHA до и после).
- Проверка на реальном логгере `logger_METRIC_EN_v371_A2WC0MME_DeltaMAP_CLEAN_SPARK.xml`: слияние прошло, SHA оригинала не изменился, в SSM-разделе 216 параметров.

### 2.2. Применимость адресов

Адреса подтверждены в коде proxy v63–v70, в том числе **v68_SPARK_CUT_ENABLED** (`rom_identify_v75.py` → все 10 якорей `true`). **Для ROM, фактически установленной в ECU, это не проверено** (§5). До проверки addon — исследовательская конфигурация без гарантии применимости.

Около 13 SSM-адресов дают примерно 20 Гц. Это быстрее оценки v74 «запрос на каждый отсчёт»: RomRaider использует непрерывный ответ ECU (fast poll), ответ ≈ (6 + N) байт по 2.083 мс плюс ≈ 8 мс накладных (подобрано по этим логам, требует подтверждения).

| Набор | N адресов | Оценка шага | Шагов 8 мс на отсчёт |
|---|---:|---:|---:|
| Минимальный: B024, B028, 94F0, B818, B821, 94E4 | 13 | ≈ 48 мс | ≈ 6 |
| Расширенный: + B80C, B810, B814, B8D8, RPM, MAP (float), IPW (float), ECT, TPS | ≈ 41 | ≈ 105 мс | ≈ 13 |

Анализатор измеряет фактический шаг каждого лога и не опирается на эти оценки. **Даже минимальный набор охватывает ≈ 6 прогонов задачи №9 на отсчёт** — восстановить отдельные события 8 мс по SSM нельзя.

## 4. Анализатор логов

`python tools/analysis/sh7055_tipin_log_analyzer_v75.py LOG.csv --rom ROM.bin --out DIR --plot`

- Время: `HH:MM:SS.mmm` RomRaider (с переходом через полночь) или миллисекунды.
- Столбцы распознаются по именам (новые E75xx и штатные E38/E54/E55/E50, обороты, MAP, IPW, ECT, TPS, широкополосный λ). Единицы приводятся: % → raw B024, мс → мкс, bar/kPa/psi → мм рт. ст. Особенность: E54 в исходном логгере подписан «%», но `expr = x`, поэтому значение считается сырым.
- **CMT1 по `94F0`:** u16 разворачивается по модулю 65536. Неатомарное чтение (скачок ±256 при переносе младшего байта) исправляется выбором ближайшего к ожидаемому кандидата. Интервалы, где возможны многократные переполнения, отбрасываются. Скорость = Σ Δcount / Σ Δt. Погрешность оценивается сверху как медианный шаг / длительность. Выводятся `implied_cmt1_tick_ms`, `implied_pphi_mhz = 0.04·rate`, `implied_task9_activation_period_ms = 4000/rate` и признак совпадения с 20 МГц (500 отсчётов/с). Если `94F0` не меняется, в отчёте «unavailable: адрес, вероятно, неверен».
- **`94E4`:** приращения с учётом насыщения 255 (тогда — нижняя граница) и уменьшений (перезапуск ECU).
- **Серии Tip-in:** событие — рост `B818`, уменьшение до значения > 0 или уменьшение `B821`. Падение `B818` до 0 — конец серии. Число событий — нижняя граница. Ограничивающий фактор (с `--rom`): лимит `B818`, лимит `B814` или «`B80C` ниже порога» — `B80C` пишется до проверки порога. В остальных случаях — `unavailable` (нужен DAQ).
- Отчёт разделён на `measured`, `counter_derived`, `model`, `unavailable`. Для SSM-лога модель не запускается.
- Синтетическая проверка: 500 отсчётов/с, 200 с, переполнения, 41 вставленный сбой ±256 → 499.998/с (82 исправленных интервала), Pφ = 19.9999 МГц. Вариант 1000/с распознаётся как 40 МГц.

## 4.1. Что доказывает SSM, а что требует внешнего DAQ

| Вопрос | SSM (≈ 10–20 Гц) | Нужен DAQ |
|---|---|---|
| Период тика CMT1 / Pφ | **да**, по `94F0` за ≥ 60 с (погрешность < 0.1 %) | — |
| Период активации задачи №9 | **да, как вычисленный** (8 тиков) | для периода **исполнения** и джиттера — нет данных ни там, ни там |
| Потери активаций | **да**, `94E4` (нижняя граница при 255) | — |
| Было ли срабатывание, сколько в серии | **да**, нижняя граница по `B818`, `B821` | точное число и время — да |
| Величина рассчитанной и поданной добавки | **да**, последние `B80C`, `B810` (защёлкнуты) | ширина реального импульса на форсунке |
| Лимит событий или накопленного Δ | **да**, по `B818` / `B814` против калибровки ROM | — |
| Какой прогон преодолел порог Δ | нет | TPS ≥ 1 кГц |
| Задержка от нажатия до импульса | нет | сигналы TPS и форсунки |
| Слияние с основным импульсом | нет | сигнал форсунки ≥ 50 кГц |
| Отклонение λ и его задержка | грубо (λ ECU 1/128) | широкополосный λ ≥ 100 Гц |

## 5. Какая ROM в автомобиле

> **Обновление v76:** по словам владельца, логи 2026-10-27 записаны на `Forester_SG9_MAP_clean_0_85_bar_v54.bin` (SHA-256 `8c4bd8e2…`). Её код проверен (`rom_code_audit_v76.py`: 28 регионов совпадают с v63/v68), и она добавлена со статусом `CODE-AUDITED`. Подробности — в [v76](sh7055-tipin-v76-first-vehicle-logs.md) §5.

- Последняя сборка с подтверждённым логом с автомобиля в `forester_A2WC012E` — **`v68_SPARK_CUT_ENABLED`** (`8f02eecf…`). В `docs/known-results.md`: «Пользователь подтвердил, что `romraiderlog_20260902_001107.csv` записан на» этой сборке.
- Более поздние: v69 CLEAN_SPARK (собрана, «awaiting vehicle validation»), v84 AF_off (только хеш, файла нет), v85 FFS (EXPERIMENTAL). Что сейчас в ECU — **неизвестно**. По имени или номеру версии это не определяется.

Порядок:
1. Считать ROM из ECU штатным средством чтения (EcuFlash + OpenPort: «Read from ECU»). Только чтение. Аккумулятор на зарядном устройстве, зажигание по инструкции программы, ничего не записывать.
2. `python tools/analysis/rom_identify_v75.py car_read.bin` (или `sha256sum` / `Get-FileHash -Algorithm SHA256`).
3. `KNOWN-PROXY` или `KNOWN-ROM` и все якоря `true` → модель и addon применимы, статус по уровню.
4. `UNKNOWN` → **не** добавлять в whitelist по ECU ID. Сначала отдельный аудит кода и адресов (листинги v69–v73 через `sh2e_disasm.py`), и только потом — новая запись с её SHA.

## 6. Первый тест (неподвижный автомобиль, без изменения ROM)

**Безопасность:** не нажимать педаль при включённом зажигании и заглушенном двигателе. Будет ли асинхронный впрыск запрещён на остановленном двигателе, не установлено (маска `B434`, v73 §4). Все тесты — на месте, P/N, ручной тормоз, исправный двигатель, проветривание.

| Шаг | Режим | Набор | Длительность | Что проверяется |
|---|---|---|---|---|
| S0 | — | — | — | ROM: SHA-256 и `rom_identify_v75.py` (§5) |
| S1 | зажигание ON, двигатель не запущен, педаль не трогать | только E7509 (`94F0`) | 2–3 мин | читается ли адрес (растёт ли счётчик); оценка CMT1 и Pφ |
| S2 | ХХ, прогретый (ECT ≥ 80 °C) | минимальный | 5 мин | CMT1 под нагрузкой ECU; рост `94E4` на ХХ |
| S3 | ХХ, N/P, перегазовки до ≤ 3000 об/мин: медленно ×10, средне ×10, резко ×10, пауза ≥ 3 с | минимальный | ≈ 5 мин | события по `B818/B821`, `B028` |
| S4 | то же, что S3 | расширенный | ≈ 5 мин | `B80C/B810/B814`, ограничивающий фактор серии |
| S5 (опц.) | то же, что S3 | минимальный + внешний DAQ (TPS, форсунка 1, λ) | ≈ 5 мин | время и ширина реальных доп. импульсов |

Критерии готовности к дорожным тестам:
- `94F0` растёт; CMT1 оценён;
- `94E4` объяснён;
- в S3/S4 видны срабатывания, а `B818/B814/B80C` не противоречат модели на той же ROM;
- лог читается анализатором без `unavailable` по основным пунктам.

Без этого дорожные испытания не начинать.

## 7. Инструкция

1. **ROM:** S0 (§5). Прислать `car_read.bin` или хотя бы вывод `rom_identify_v75.py`.
2. **Логгер:** не меняя свой файл, выполнить
   `python tools/romraider/merge_logger_addon.py <ваш_logger.xml> tools/romraider/logger_A2WC0MME_dkmode_tipin_v75_addon.xml <новый_logger.xml>`.
   В RomRaider указать `<новый_logger.xml>` как Logger Definition. Подключиться и убедиться, что в списке есть «DKmode …» (E7501–E7510) и они читаются.
3. **Наборы:** минимальный — E7501, E7502, E7506, E7507, E7508, E7509. Расширенный — плюс E7503, E7504, E7505, E7510, Engine Speed, MAP (4-byte), IPW (4-byte), Coolant, Throttle Opening Angle и внешний широкополосный λ.
4. **Запись:** шаги S1–S4, отдельный CSV на каждый шаг; в имени файла указать шаг. Записать: время и тип каждой перегазовки, ECT, модель широкополосника.
5. **Передать для анализа:** CSV, использованный `<новый_logger.xml>` (или его SHA), вывод `rom_identify_v75.py`, заметки по шагам, при наличии — файлы DAQ (CSV `t_ms,tps_pct,…` и сигнал форсунки).
6. **Анализ:** `python tools/analysis/sh7055_tipin_log_analyzer_v75.py S3.csv --rom car_read.bin --out reports/ --plot`.

## 8. Открытые ограничения

- Применимость адресов к ROM в ECU (§5) — главный блокирующий пункт.
- Накладные расходы fast poll (≈ 8 мс) подобраны по старым логам — уточнить на первом логе.
- Период исполнения и джиттер задачи №9 по SSM не измеряются: доступен только период активации и счётчик потерь.
- Запрещён ли асинхронный впрыск при остановленном двигателе — не установлено (поэтому педаль при неработающем двигателе не трогать).
- CarBerry: выводы о сравнении по-прежнему требуют оригинального BIN (v74 §4).
- Hardware Manual: смысл режимных битов PFC, PKIR и битов ATU-II (v74 §8).
